# Results And Report Interpretation

UltraViolet results can be read from the terminal or exported with the `wr` command.

The `wr` command writes four files using the prefix you enter:

```text
<prefix>_network.<timestamp>.csv
<prefix>_invoice.<timestamp>.csv
<prefix>_nodes.<timestamp>.csv
<prefix>_all.<timestamp>.txt
```

The timestamp uses `yyyyMMddHHmm`.

## Network Report

The network report is a table of summary statistics:

```text
Value          Min            Max            Average        Std Deviation  1st quartile   median         3rd quartile
Graph Nodes    83             100            96.65          5.15           94.00          99.00          100.00
Graph Channels 507            1780           1299.49        406.00         939.00         1390.00        1692.00
Node Channels  1              70             17.80          16.13          7.00           11.00          24.00
Node Capacity  70000          532280000      74599000.00    99454340.31    6520000.00     26540000.00    103340000.00
LN balance     70000          473328358      37299500.00    70795154.54    2653602.00     5851155.00     46101542.00
Invoices       32             67             50.00          7.13           44.00          50.00          56.00
Outbound %     0              1              0.46           0.24           0.25           0.46           0.60
```

Interpretation:

- `Graph Nodes` and `Graph Channels` describe what each node can see in its local graph.
- `Node Channels` counts actual local channels per node.
- `Node Capacity` is the sum of channel capacity touching each node.
- `LN balance` is local balance from the node point of view.
- `Invoices` counts generated invoices per node.
- `Outbound %` is local balance divided by node capacity.

## Invoice Report

The invoice report is a CSV where each row is one processed invoice from the sender point of view. See `invoice_report_format.md` for the complete schema.

Example:

```csv
hash,sender,dest,amt,max_fees,path_finder,search_limit_paths,search_returned_paths,...
4b..1d,pk0,pk74,888862,1000,lnd,64,7,...
```

Interpretation:

- `search_*` fields describe graph search behavior.
- `filtered_*` fields describe sender-side post-search rejection.
- `attempt_*` fields describe actual HTLC attempt outcomes.
- `success` is the final invoice result.

Do not add the `search_excluded_*` fields and interpret them as paths. They are search-stage counters.

## Node Report

The node report is a CSV with one row per node:

```csv
PubKey,Alias,Capacity,Channels,OutboundFraction,Max,Min,Average,Median,invoice_processing_success,...
pk0,Double meanings,90310000,23,0.10,12100000,10000,3926522,3900000,19,...
```

Interpretation:

- `Capacity` is total capacity touching the node.
- `Channels` is local channel count.
- `OutboundFraction` is local balance divided by node capacity.
- `Max`, `Min`, `Average`, and `Median` summarize channel sizes for that node.
- The remaining fields summarize invoice processing and forwarding outcomes.

## All Report

The all report is a text dump of every node and channel:

```text
Pubkey     Alias                          Node Capacity        Channels        Node Profile
pk0        Double meanings                90,310,000           23              medium
Channel ID      Node 1 Node 2 balances             n1 base/ppm  n2 base/ppm
ch_pk0_pk1      pk0    pk1    2891962    308038     100   320    100   295
```

Interpretation:

- Each channel row shows endpoint ids, endpoint balances, and fee policies.
- Balance columns are from `node1` and `node2` storage order, not necessarily the currently displayed node's local/remote perspective.
- Use the interactive `node` command when you need a local outbound/inbound view.

## Comparing Runs

For scientific comparisons:

- compare reports generated by the same code version;
- keep config files with the reports;
- record seed values, but do not assume full threaded replay determinism;
- compare scenario-level distributions, rates, and summary statistics, not log line ordering.
